# PeopleOps AI — User Interface Specification (UI)

## 1. Objetivo
El frontend debe hacer visibles análisis, evidencia, políticas, Human Review y trazabilidad.

Aplicación: `peopleops-web`.

Consume exclusivamente `peopleops-api`.

## 2. Navegación MVP
- Dashboard / Home
- Analysis
- Analysis History
- Policies
- Human Review

No se requiere frontend para Reference MCP Server.

## 3. Analysis
### Input
- pregunta;
- contexto conversacional cuando aplique;
- submit/cancel.

### Response
- answer;
- status;
- key findings;
- warnings;
- Human Review state.

### Evidence tabs
- Data Evidence;
- Policy Evidence;
- Analysis Details.

No mostrar chain-of-thought.

## 4. Data Evidence
Mostrar:
- provider;
- período;
- capabilities consultadas;
- métricas;
- resultados estructurados;
- warnings.

No es obligatorio mostrar SQL físico.

## 5. Policy Evidence
Mostrar:
- título;
- versión;
- vigencia;
- página/sección;
- fragmento;
- link/open source.

Debe adaptar el patrón de evidencia visible validado en Enterprise RAG.

## 6. Policies
Funciones:
- listar/buscar;
- upload;
- metadata;
- versiones;
- status;
- effective dates;
- ingestion status;
- view original;
- reindex si falla.

El documento fuente sigue siendo autoridad; no sustituirlo por edición manual de chunks.

## 7. Human Review Inbox
Lista:
request, employee/context, reason, status, created_at, sensitivity.

Detalle:
- question;
- facts;
- policy evidence;
- recommendation;
- missing information;
- warnings.

Acciones:
- Approve;
- Reject;
- Needs information.

## 8. Analysis History
Mostrar:
- request_id;
- question;
- created_at;
- status;
- current_stage;
- duration;
- review state.

Detalle:
- answer;
- evidence;
- stage timeline;
- warnings/errors seguros.

No mostrar prompts internos ni chain-of-thought.

## 9. Dashboard
Puede mostrar:
- análisis recientes;
- reviews pendientes;
- ingestion failures;
- system health básico.

No construir un BI HR.

## 10. UI States
received, running, pending_human_review, completed, failed, insufficient_data, permission_denied.

## 11. Usabilidad
- responsive desktop-first;
- keyboard usable;
- loading/error states claros;
- no depender solo del color;
- confirmación en decisiones Human Review.

## 12. Security UX
- ocultar payroll sin autorización;
- limitar evidencia sensible por scope;
- no stack traces;
- validar uploads;
- advertir documentos no procesados.

## 13. Fuera de alcance
- MCP admin console;
- visual schema designer;
- semantic mapping editor;
- full HR dashboard;
- payroll editing;
- employee master maintenance;
- recruiting/performance modules.
